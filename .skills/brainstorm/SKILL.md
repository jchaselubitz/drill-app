# Brainstorm Skill

<brainstorm>

When the user presents an idea, concept, or problem they want to explore, follow this three-phase structured brainstorming process. Each phase should be clearly delineated with a header.

## Phase 1: Recompose the Idea

Restate the user's idea in your own words. The goal is NOT to parrot it back — it's to demonstrate understanding by restructuring and clarifying it. This serves two purposes:

1. **Validation** — the user can confirm you understood correctly before you build on it
2. **Refinement** — by recomposing, you often surface implicit assumptions, clarify scope, and tighten the concept

Guidelines:
- Distill the core proposition into 2-4 sentences
- Name any implicit assumptions you're detecting
- If the idea has multiple parts, break them out explicitly
- If the idea is vague, pick the strongest interpretation and state it — don't ask for clarification yet
- Use the header: **"Here's what I'm hearing"**

## Phase 2: Straight Response

Respond to the idea as you normally would — with your honest, direct assessment. This is the "conventional wisdom" pass.

Guidelines:
- Be direct about strengths and weaknesses
- Flag obvious risks or gaps
- Mention relevant precedent, comparable products/ideas, or known patterns
- If you have a strong opinion, state it and say why
- Keep this grounded and practical
- Use the header: **"My take"**

## Phase 3: Orthogonal Perspectives

This is the core value of the skill. Propose 3-5 ways of thinking about the same idea that come from fundamentally different angles. These should NOT be variations or iterations — they should be genuinely orthogonal reframings.

Orthogonal means: a different axis of thinking, not a different point on the same axis.

### Types of orthogonal shifts to draw from:

- **Inversion** — What if the opposite of this idea is actually the right move?
- **Audience shift** — What if this was built for a completely different user/market?
- **Timescale shift** — What does this look like in 6 months vs 10 years? What if you only had 2 weeks?
- **Abstraction shift** — Zoom way out (what general problem is this solving?) or zoom way in (what's the atomic unit of value here?)
- **Analogy from another domain** — What's the equivalent of this in biology, urban planning, game design, etc.?
- **Constraint flip** — What if the thing you're treating as a constraint is actually the feature? Or vice versa?
- **Stakeholder swap** — How would your biggest critic see this? Your most enthusiastic user? A regulator?
- **Economic reframe** — What if the business model was completely different? What if it was free? What if it was 10x the price?
- **Technology shift** — What if you had to build this with no code? With only AI? With 1990s tech?

Guidelines:
- Label each perspective clearly with a short, punchy name
- For each, give 2-4 sentences explaining the reframe and why it's interesting
- At least one perspective should be uncomfortable or counterintuitive
- Don't hedge — commit to each frame and make it compelling, even if you'd ultimately argue against it
- Use the header: **"Orthogonal angles"**

## Conversation Flow

After completing all three phases, pause and let the user react. Common follow-ups:
- The user wants to drill into one of the orthogonal angles → explore it in depth
- The user wants to combine angles → help synthesize
- The user corrects the recomposition → re-run from Phase 1 with the correction
- The user has a new idea → start fresh from Phase 1

Do NOT ask "which angle interests you?" or similar. Just deliver the three phases and let the user drive.

## Tone

- Direct, not academic
- Opinionated, not neutral
- Concise, not padded
- Creative, not formulaic — avoid generic business-speak like "leverage", "synergy", "unlock value"
